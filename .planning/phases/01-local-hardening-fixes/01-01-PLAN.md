```python
import nh3

# Constructor signature (relevant kwargs for D-01..D-03):
#   nh3.Cleaner(
#       tags: set[str] | None = None,            # allowed tag names; non-listed tags are stripped
#       attributes: dict[str, set[str]] | None = None,  # per-tag attr allowlist; key "*" applies to all tags

#   .clean(html: str) -> str
```

The nh3 default `url_schemes` already includes http, https, mailto, tel, etc. and excludes
`javascript:` and `data:`, so D-02's "http:// or https:// only" requirement for <a href> is
satisfied by the default — no `url_schemes` kwarg needed. Non-conforming hrefs are stripped
from the attribute, leaving the `<a>` tag with link text intact.

`data-p-id` is allowed via `attributes={"*": {"data-p-id"}}` rather than the broader
`generic_attribute_prefixes={"data-"}` (RESEARCH §"Anti-Patterns to Avoid").

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Wattpad HTTP response → `extract_chapter()` | Untrusted HTML from Wattpad's chapter endpoint crosses into our parser/storage layer |
| Stored paragraph JSON → renderer (HTML/EPUB) | Sanitized HTML is replayed into output artifacts opened in user's reader/browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering / Information disclosure (stored XSS) | `local_story_archive/scrape/chapter_html.py:extract_chapter` (paragraph HTML stored verbatim, rendered into HTML/EPUB output) | high | mitigate | Module-scope `nh3.Cleaner` with allowlist `tags={img,br,b,i,em,strong,u,a}`, attrs `{img:{src,alt}, a:{href}, *:{data-p-id}}`, default `url_schemes` (excludes `javascript:`/`data:`). Per-paragraph `.clean(html)` call before storage. |
| T-01-02 | Information disclosure (active-content link rel) | sanitized `<a>` tags in EPUB/HTML output opened in browser | low | mitigate | nh3 default `link_rel="noopener noreferrer"` left in place — defense in depth even though sanitized output is already clean. |
| T-01-03 | Tampering (data-* allowlist over-broad) | nh3 `attributes` config for `data-p-id` | low | mitigate | Use explicit `attributes={"*": {"data-p-id"}}` (not `generic_attribute_prefixes={"data-"}`) so only `data-p-id` is allowed; future `data-tracking-id`-style attrs are stripped. |
| T-01-04 | Denial of service (oversized HTML triggering nh3 OOM) | per-paragraph `.clean()` call | low | accept | Wattpad paragraphs are small (typically < 4 KB). nh3 is Rust-backed; no observed OOM on realistic inputs. Out of scope for Phase 1. |
</threat_model>

    ```python
    import logging
    from dataclasses import dataclass

    import nh3
    from bs4 import BeautifulSoup

    logger = logging.getLogger(__name__)

    # Phase 1 SAN-01: paragraph HTML allowlist. Reading-rich tags (D-01),
    # per-tag attributes (D-02), data-p-id allowed on every tag (D-02),
    # class/style stripped from all tags (D-03). nh3's default url_schemes
    # already excludes javascript:/data: so the D-02 "http/https only for
    # <a href>" requirement is satisfied without a custom url_schemes set —
    # invalid schemes drop the attribute, preserving link text.
    _PARAGRAPH_CLEANER = nh3.Cleaner(
        tags={"img", "br", "b", "i", "em", "strong", "u", "a"},
        attributes={
            "img": {"src", "alt"},
            "a": {"href"},
            "*": {"data-p-id"},
        },
        strip_comments=True,
    )


    @dataclass
    class ChapterContent:
        text: str
        paragraphs: list[dict]    # [{"id": str, "text": str, "html": str}]
        images: list[str]


    def extract_chapter(html: str) -> ChapterContent:
        soup = BeautifulSoup(html, "lxml")
        container = soup.select_one(".page-container") or soup.body
        if container is None:
            return ChapterContent(text="", paragraphs=[], images=[])

        paragraphs: list[dict] = []
        images: list[str] = []

        # Match anything with a data-p-id attribute. Wattpad has used both <pre>
        # and <p> in different layouts; the attribute is the reliable selector.
        para_els = container.find_all(attrs={"data-p-id": True})

        if not para_els:
            logger.warning(
                "extract_chapter: no elements with data-p-id found; "
                "Wattpad HTML structure may have changed"
            )

        for para in para_els:
            pid = para.get("data-p-id", "")
            for img in para.find_all("img"):
                src = img.get("src", "")
                if src:
                    images.append(src)
            raw_html = para.decode_contents()
            clean_html = _PARAGRAPH_CLEANER.clean(raw_html)  # SAN-01: D-04
            paragraphs.append({
                "id": pid,
                "text": para.get_text(" ", strip=True),
                "html": clean_html,
            })
        text = "\n\n".join(p["text"] for p in paragraphs if p["text"])
        return ChapterContent(text=text, paragraphs=paragraphs, images=images)
    ```

    Key invariants:
    - `_PARAGRAPH_CLEANER` is at module scope (constructed once at import; reused for every paragraph for the entire process lifetime — RESEARCH §"Pattern 1")
    - Use `attributes={"*": {"data-p-id"}}` exactly — NOT `generic_attribute_prefixes={"data-"}` (would widen the surface; D-02 is explicit)
    - Do NOT pass `url_schemes=...` — the nh3 default already implements D-02's "http/https only" rule and rejects javascript:/data:
    - Do NOT pass `link_rel=None` — leave the default `"noopener noreferrer"` (RESEARCH §"Pitfall 1": defense in depth)
    - The `images` list is still populated from BeautifulSoup pre-sanitization (we want all referenced URLs for the cover/asset pipeline; sanitization runs only on the stored `html` field)
    - The `text` field still uses `para.get_text()` (BeautifulSoup-extracted plain text) — sanitization does not affect it

    Run `ruff check local_story_archive/scrape/chapter_html.py` and `ruff format local_story_archive/scrape/chapter_html.py` after the edit.
